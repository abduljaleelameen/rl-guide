## Training Optimization

Learn how to train faster, use less memory, and achieve better results through hyperparameter tuning and optimization techniques.

## Memory Optimization

<Tabs items={['4-bit Quantization', 'Gradient Checkpointing', 'LoRA Rank Tuning']}>
  <Tab value="4-bit Quantization">
    ### 4-bit Quantization (QLoRA)

    Reduces model memory by 75% with minimal quality loss.

    ```python
    from unsloth import FastLanguageModel

    model, tokenizer = FastLanguageModel.from_pretrained(
        model_name="Qwen/Qwen2.5-3B-Instruct",
        load_in_4bit=True,  # 75% memory reduction
        dtype=None,         # Auto-detect optimal dtype
    )
    ```

    **Memory Comparison:**
    | Model Size | FP16 (GB) | 4-bit (GB) | Savings |
    |------------|-----------|------------|---------|
    | 3B params | 12 GB | 3 GB | 75% |
    | 7B params | 28 GB | 7 GB | 75% |
    | 14B params | 56 GB | 14 GB | 75% |

    <Callout type="success">
      **Recommendation:** Always use 4-bit for models 3B+. Quality degradation is negligible (&lt;1%) for RL training.
    </Callout>
  </Tab>

  <Tab value="Gradient Checkpointing">
    ### Gradient Checkpointing

    Trades compute for memory by recomputing activations during backward pass.

    ```python
    model = FastLanguageModel.get_peft_model(
        model,
        use_gradient_checkpointing="unsloth",  # Optimized implementation
        # ... other params
    )
    ```

    **Impact:**
    - Memory: -40% (saves ~8GB on 7B model)
    - Speed: -15% (slightly slower due to recomputation)
    - **Net:** Can train larger batch sizes → faster overall

    **When to Use:**
    - Always for models 7B+
    - When hitting OOM errors
    - When you want larger batch sizes
  </Tab>

  <Tab value="LoRA Rank Tuning">
    ### LoRA Rank Selection

    Lower rank = less memory, faster training, but potentially lower quality.

    ```python
    model = FastLanguageModel.get_peft_model(
        model,
        r=16,  # LoRA rank (8, 16, 32, 64)
        # Lower rank = less memory
    )
    ```

    **Rank Guidelines:**

    | Rank | Memory | Quality | Use Case |
    |------|--------|---------|----------|
    | 8 | Minimal | Good | Simple tasks (sentiment, classification) |
    | 16 | Low | Great | Most RL tasks (recommended) |
    | 32 | Medium | Excellent | Complex reasoning, coding |
    | 64 | High | Best | Multi-domain, production |

    **Rule of Thumb:**
    - Start with r=16
    - Increase to r=32 if validation reward plateaus
    - Only use r=64 for production deployments
  </Tab>
</Tabs>

## Hyperparameter Tuning

### Critical Hyperparameters

<Cards>
  <Card title="Learning Rate">
    **Most important parameter for stable training.**

    ```python
    # Conservative (safer)
    learning_rate=1e-6

    # Standard (recommended)
    learning_rate=5e-6

    # Aggressive (faster, riskier)
    learning_rate=1e-5
    ```

    **Guidelines:**
    - Start with 5e-6
    - Lower if loss becomes NaN
    - Higher if training too slow
    - Use learning rate scheduler for long training
  </Card>

  <Card title="num_generations">
    **Number of responses per prompt (GRPO-specific).**

    ```python
    # Fast but noisy
    num_generations=4

    # Balanced (recommended)
    num_generations=8

    # Stable but slow
    num_generations=16
    ```

    **Trade-offs:**
    - Higher = better advantage estimates
    - Higher = more VRAM usage
    - Higher = longer training time
    - Sweet spot: 8-12 for most tasks
  </Card>

  <Card title="Temperature">
    **Controls exploration vs exploitation.**

    ```python
    # Focused (math, code)
    temperature=0.8

    # Balanced (recommended)
    temperature=1.0

    # Exploratory (creative tasks)
    temperature=1.3
    ```

    **By Task Type:**
    - Math/Code: 0.8-1.0
    - General QA: 1.0-1.2
    - Creative writing: 1.2-1.5
  </Card>

  <Card title="KL Coefficient">
    **Prevents model from drifting too far from base.**

    ```python
    # Weak constraint
    kl_coef=0.01

    # Standard (recommended)
    kl_coef=0.05

    # Strong constraint
    kl_coef=0.1
    ```

    **When to Adjust:**
    - Increase if model degrading
    - Decrease if learning too slowly
    - Monitor KL divergence in logs
  </Card>
</Cards>

### 2. Increase Batch Size

Utilize full GPU capacity:

```python
config = GRPOConfig(
    per_device_train_batch_size=4,  # Increase if VRAM allows
    gradient_accumulation_steps=4,   # Effective batch = 4 × 4 = 16
)
```

**Finding Optimal Batch Size:**
```python
# Start small and increase until OOM
for batch_size in [1, 2, 4, 8]:
    try:
        config = GRPOConfig(per_device_train_batch_size=batch_size)
        # Try one training step
        print(f"Batch size {batch_size}: SUCCESS")
    except torch.cuda.OutOfMemoryError:
        print(f"Batch size {batch_size}: OOM")
        break
```

### 2. Reward Shaping

Design rewards for faster learning:

```python
def shaped_reward(prompts, outputs, **kwargs):
    """Well-shaped reward function"""
    rewards = []

    for output in outputs:
        # Start with base reward
        reward = base_correctness_check(output)

        # Add intermediate milestones
        if "step 1" in output:
            reward += 0.3  # Reward showing work

        if "final answer" in output:
            reward += 0.2  # Reward structure

        # Normalize to [-1, 3] range
        reward = max(-1, min(3, reward))

        rewards.append(reward)

    return rewards
```

**Reward Shaping Principles:**
- Provide intermediate rewards (not just final)
- Use graduated scaling (not binary)
- Normalize to consistent range
- Avoid sparse rewards

### Reward Scaling

Prevent reward explosion:

```python
class AdaptiveRewardScaler:
    def __init__(self):
        self.reward_history = []

    def scale_rewards(self, rewards):
        """Adaptive reward normalization"""
        self.reward_history.extend(rewards)

        # Keep last 1000 rewards
        if len(self.reward_history) > 1000:
            self.reward_history = self.reward_history[-1000:]

        # Normalize to zero mean, unit variance
        mean = np.mean(self.reward_history)
        std = np.std(self.reward_history) + 1e-8

        scaled = [(r - mean) / std for r in rewards]
        return scaled
```

### Red Flags

Monitor for these warning signs:
- **Reward std → 0:** Mode collapse
- **KL div > 10:** Drifting from base model
- **Loss = NaN:** Training instability
- **Tokens/sec < 100:** Bottleneck in generation
