### Key Innovations

1. **Multi-stage RL:** Base → SFT → Cold-start RL → Full GRPO
2. **Dynamic reward scaling:** Adjusted based on task difficulty
3. **Domain mixing:** Math, coding, reasoning, general QA
4. **Zero discovery:** Model learned DeepSeek-Zero technique autonomously

<Callout type="success" title="Result">
  Matches GPT-4 on reasoning benchmarks. First open-source model with competitive long-form reasoning.
</Callout>

### Technical Approach

```python
# DeepSeek R1's approximate training pipeline

# Stage 1: Base pre-training
# - 30T tokens
# - Standard next-token prediction

# Stage 2: Supervised Fine-Tuning
sft_config = SFTConfig(
    num_train_epochs=2,
    dataset="reasoning_demonstrations",  # Human-written reasoning
)

# Stage 3: Cold-start RL (conservative)
cold_start_config = GRPOConfig(
    learning_rate=1e-6,  # Very conservative
    kl_coef=0.1,         # Strong KL constraint
    num_generations=8,
)

# Stage 4: Full RL (production)
full_config = GRPOConfig(
    learning_rate=5e-6,
    kl_coef=0.05,
    num_generations=16,
    temperature=1.0,
)

# Domain mixing with weighted sampling
domain_weights = {
    'math': 0.40,
    'code': 0.30,
    'reasoning': 0.20,
    'general': 0.10,
}
```

### Lessons Learned

- **Cold-start RL is critical:** Jumping straight to full RL causes instability
- **Domain mixing prevents collapse:** Single-domain training leads to brittle models
- **Scale matters:** 671B parameters enabled emergent reasoning capabilities
- **Verifiable rewards work best:** Math and code verification > subjective scoring

### Implementation Details

```python
def support_bot_reward(prompts, outputs, correct_info, **kwargs):
    """Multi-metric reward for customer support"""
    rewards = []

    WEIGHTS = {
        'correctness': 0.50,  # Must include correct info
        'brevity': 0.30,      # Keep it short
        'tone': 0.20,         # Professional and friendly
    }

    for output, correct in zip(outputs, correct_info):
        metrics = {}

        # Correctness: Does it include key information?
        key_phrases = correct.lower().split(',')
        metrics['correctness'] = sum(
            1 for phrase in key_phrases if phrase in output.lower()
        ) / len(key_phrases) * 3.0

        # Brevity: Target 30-60 words
        word_count = len(output.split())
        if 30 <= word_count <= 60:
            metrics['brevity'] = 3.0
        elif 20 <= word_count <= 80:
            metrics['brevity'] = 2.0
        else:
            metrics['brevity'] = 0.5

        # Tone: Positive sentiment + professional language
        from textblob import TextBlob
        sentiment = TextBlob(output).sentiment.polarity
        casual = any(w in output.lower() for w in ['hey', 'gonna', 'wanna'])

        if sentiment > 0.1 and not casual:
            metrics['tone'] = 3.0
        elif sentiment >= 0:
            metrics['tone'] = 2.0
        else:
            metrics['tone'] = 0.5

        # Weighted combination
        reward = sum(metrics[m] * WEIGHTS[m] for m in WEIGHTS)
        rewards.append(reward)

    return rewards
```

### Key Takeaways

- **Small data works:** Only 500 examples needed significant improvement
- **Multi-metric is essential:** Real products need to balance multiple objectives
- **Fast iteration:** 8 hours from start to production
- **Measurable ROI:** Clear business metrics (resolution time, satisfaction)

## Case Study 3: Python Code Generator

<div className="p-6 rounded-lg bg-cyan-500/10 border-l-4 border-cyan-500 my-6">
  **Company:** Developer tools startup

  **Challenge:** Model generated syntactically correct but non-functional code (didn't pass tests).
</div>

### RL Approach with Execution Verification

- **Reward Function:** Run generated code in sandbox, check if tests pass
- **Graduated Rewards:** +3 all tests pass, +1.5 some pass, -1 none pass, -2 syntax error
- **Safety:** Docker sandbox with 5-second timeout
- **Data:** 2,000 LeetCode-style problems with test cases

### Results (Pass@1 on HumanEval)

| Stage | Pass Rate | Improvement |
|-------|-----------|-------------|
| Base Model (CodeLlama 13B) | 45.2% | — |
| After SFT | 52.8% | +7.6% |
| After GRPO with Execution | 68.3% | +23.1% |

<Callout type="success" title="Key Insight">
  Execution-based rewards (verifiable) work better than code quality metrics. The model learned to actually solve problems, not just generate plausible-looking code.
</Callout>

### Implementation

```python
import docker
import subprocess

def code_execution_reward(prompts, outputs, test_cases, **kwargs):
    """Execute code and reward based on test results"""
    rewards = []
    client = docker.from_env()

    for output, tests in zip(outputs, test_cases):
        try:
            # Extract code from output
            code = extract_code_block(output)

            # Run in Docker sandbox
            container = client.containers.run(
                "python:3.11-slim",
                f"python -c '{code}'",
                timeout=5,
                mem_limit="128m",
                detach=True
            )

            # Wait for completion
            result = container.wait(timeout=5)
            logs = container.logs().decode()

            # Run test cases
            passed = 0
            for test_input, expected_output in tests:
                if run_test(code, test_input, expected_output):
                    passed += 1

            # Graduated rewards
            if passed == len(tests):
                reward = 3.0  # All tests pass
            elif passed > len(tests) / 2:
                reward = 1.5  # Most tests pass
            elif passed > 0:
                reward = 0.5  # Some tests pass
            else:
                reward = -1.0  # No tests pass

        except SyntaxError:
            reward = -2.0  # Syntax error
        except TimeoutError:
            reward = -1.5  # Timeout (infinite loop)
        except Exception:
            reward = -1.0  # Runtime error

        rewards.append(reward)

    return rewards
```

### Scaling to Production

After successful pilot:
- Deployed to 10,000 daily users
- Average 68% first-attempt success rate
- Reduced user iteration time by 60%
- Enabled "code explanation" feature (model learned to comment code)

## Common Patterns Across Cases

### 1. Multi-Stage Training

All successful deployments used progressive training:
```
Base Model → SFT (optional) → Cold-start RL → Full RL
```

### 2. Domain-Specific Rewards

Generic rewards don't work well. Each case needed custom reward functions:
- DeepSeek: Math verification + code execution
- E-commerce: Brevity + correctness + tone
- Code gen: Test execution + syntax checking

### 3. Rapid Iteration

Successful teams iterated quickly:
- Start with small datasets (50-500 examples)
- Train for 2-8 hours
- Deploy canary (5% traffic)
- Measure, learn, repeat

### 4. Production Infrastructure

All required:
- Automated testing pipelines
- Canary deployments
- Rollback capabilities
- Monitoring dashboards
